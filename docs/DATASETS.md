# Datasets

The only supplied corpus is twelve original fictional smoke documents under examples/corpus, licensed CC0-1.0. It is repetitive and unsuitable for language-generalization measurement. No production corpus or pretrained tokenizer is supplied.

Input is UTF-8 text documents or JSONL text records. Identical SHA256 document groups are deduplicated before deterministic splitting. The sorted-hash 10% holdout changes if documents are added; freeze the corpus. Fit BPE exclusively on training text. Prepared manifests bind token arrays to tokenizer fingerprints. BOS/document/EOS packing permits causal attention across document boundaries. Tails are unused, with count `(tokens-1) % sequence`.

The legacy corpus importer retains text in RAM; production curation below is disk-backed. Large-scale work requires bounded-memory manifests/shards, source/license records, near-duplicate and contamination checks, frozen evaluation families, and review of redistribution rights. Arithmetic holdouts canonicalize addition operands and partition identities independently of random ordering; this does not establish generalization across equivalent word problems.

## M3 production workflow

`data curate --config CONFIG --output DIR [--resume]` streams UTF-8 JSONL, bounded text paragraphs or optional Parquet batches into SQLite. Text paragraphs retain their source-file split group. Each source needs name, snapshot, license, attribution and paths. A row may provide a split/group identity; declared validation/test sources are processed before training. `configs/data/example.yaml` is a template requiring reviewed local paths.

SQLite stores text, identities, quality decisions, deduplication indexes and committed source cursors. It is the durable spool as well as the index, avoiding a second text copy and a cross-file commit protocol. JSONL/text restart at committed byte offsets; Parquet skips completed row groups and replays at most its current group. Source/configuration hashes must match. Invalid UTF-8/JSON, missing/short/oversize text, NUL/replacement corruption and extreme repetition are counted separately. Text is preserved; normalized whitespace is used only for duplicate identity. Maximum document size defaults to 1 MiB; oversized Parquet row groups require repartitioning. These limits and filtering counts must be reviewed for the intended corpus.

Exact duplicates are global. Long documents (at least 128 lexical/operator tokens) use 64 deterministic MinHash projections in 16 bands; candidates require verified five-token-shingle Jaccard similarity ≥0.85. One representative is retained. Short mathematics retains exact checking only. This approximate, representative-based detector can miss matches and transitive chains; it is not a completeness guarantee. Protected evaluation text must be supplied as declared holdout sources. A second disk-backed pass removes training documents sharing any 13-token span with retained holdouts. Shorter embedded questions and semantic equivalence remain limitations; production review must address them before the pilot.

Default hash splits are 99/0.5/0.5 percent, grouped by document or supplied parent identity. Declared upstream splits are preserved. The curated immutable database checksum binds all retained split identities. A changed input requires a new dataset; resume cannot silently add new files. Empty splits fail instead of being silently rebalanced.

`tokenizer train --dataset DIR --vocab-size 16384 --output FILE` fits a byte BPE candidate from training only, with an explicit 32 MiB fitting sample budget. Iterator ingestion does not imply constant-memory native BPE statistics; measure fitting memory before increasing the budget. Initial byte alphabet and PAD/UNK/BOS/EOS IDs 0/1/2/3 are preserved. No pretrained tokenizer is imported. Literal reserved-token strings retain legacy special-token semantics.

`tokenizer evaluate --dataset DIR --tokenizer FILE` measures validation round trips, tokens per character/document and fixed arithmetic/Unicode expression fragmentation. `tokenizer freeze` creates a non-overwriting candidate directory, tokenizer and checksummed identity/provenance. Production acceptance is a separate decision. Modifying a frozen tokenizer invalidates preparation; training additionally checks tokenized-manifest fingerprints.

`data prepare --dataset DIR --tokenizer FILE --output NEW_DIR [--resume]` writes little-endian uint16 shards (target 128 MiB), per-document offset indexes and checksum manifests. BOS/document/EOS boundaries are explicit; attention can cross documents. The final incomplete sequence is unused. Resume verifies committed shards and restarts at the first uncommitted document; completed documents are not retokenized. A final manifest is published atomically. Do not run competing writers against one output directory.

`data verify --data DIR` checks schema, sizes and checksums. The training reader maps at most four shards at once, assembles sequence-plus-lookahead windows across shard boundaries and shifts exactly once. Startup hashes all shards, trading startup I/O for integrity. Legacy uint32 arrays and original checkpoint fingerprints remain supported.

### Actual bounded validation

WikiText-2 raw was fetched at revision b08601e04326c79dfdd32d625aee71d232d685c3: **7,747,362 downloaded bytes**, below the approved 100 MiB cap. Original paragraphs were grouped into articles; upstream splits were retained. Source files, reconstruction config, candidate and run evidence are ignored under outputs/m3. The dataset card declares CC-BY-SA-3.0/GFDL in metadata and CC-BY-SA-4.0 in prose; both declarations are recorded, not silently resolved. No external text is redistributed in Git. [Publisher card](https://huggingface.co/datasets/Salesforce/wikitext).

The real 16,384-token candidate measured 0.227400 tokens/character over 60 held-out documents. Example token counts: `12 + 34 = 46`: 5; `0.125 × 8 = 1`: 8; `x² + y² = z²`: 11; `∫ x dx = x²/2 + C`: 14. These are fragmentation measurements, not reasoning results. A tiny new-loader CPU model completed 40 updates (last loss 7.90737 after a 20-step stop/resume); it is not a trained 250M model.

### Planning and remaining gates

Provisional 5B mixture: 70% educational/general web, 20% encyclopedia and 10% licensed human reference/STEM text. FineWeb-Edu is a candidate under its ODC-By/CommonCrawl terms; Wikipedia and textbooks have their own attribution and distribution terms. Model-generated mathematics and benchmark answers are excluded by default. No mixture is approved merely by being named. [FineWeb-Edu card](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu).

Five billion uint16 IDs require 10 GB (9.31 GiB) plus offsets, holdouts and manifests. A 3–6 byte/token assumption gives 15–30 GB raw text; this is an estimate to replace with measured mixture statistics. SQLite text/signature/band indexes, temporary files and checkpoints require additional space. Reserve at least 150 GB pending measured index expansion and retention needs; the inspected workspace had about 243 GB free. CPU ingestion uses bounded batches and an 8 MiB SQLite page cache; native token fitting needs separate measurement. Host capacity is about 32 GiB.

Primary FP32 weights/gradients/Adam total about 3.71 GiB before activations and runtime overhead. Historical 2K measurements were approximately 20.8k–26.4k tokens/s, giving 53–67 hours for 5B tokens before validation, checkpointing, thermal effects and sustained-load regressions. These are theoretical extrapolations from short tests. A native checkpoint is roughly 3 GB; saving every 50 steps causes substantial disk writes. Review cadence/retention and bounded evaluation before a pilot; primary defaults are unchanged.

Before the 100M-token pilot: approve corpus rights and composition; independently audit embedded/semantic contamination; validate representative tokenizer quality and fitting memory; measure production-scale preparation/index growth and sustained throughput; review frozen evaluation sampling and checkpoint cadence. The optional `stage_huggingface` adapter accepts a caller-supplied HF iterable, materializes JSONL with a payload cap and requires provenance; upstream network buffering remains the caller’s responsibility. Normal curation uses local snapshots. `data sample` explicitly downloads only the pinned WikiText-2 files with a hard byte budget. Comprehensive external benchmark-target scanning remains a review gate. This M3 implementation does not close those gates or authorize the pilot.

The audited sample retained 516 train, 60 validation and 62 test articles; 100 training articles were excluded by protected-span overlap, one record by corruption and 15 by length. CUDA/BF16 TUI acceptance completed 80 updates with checkpoint/validation events and terminal restoration (last loss 7.75820). These smoke losses establish execution, not base-model ability.

Synthetic ingestion measurements in fresh processes: 999 documents, 35.18 MiB peak RSS, 0.207 s; 99,999 documents, 44.45 MiB peak RSS, 13.85 s. Both disable near-duplicate/span indexing to isolate ingestion; they do not measure production deduplication cost. `python scripts/check_data_memory.py --documents 100000 --output outputs/datasets/memory-NEW` reproduces the bounded check. Production-scale deduplication/index timing remains unmeasured.

An independent fit on the audited 516-document training split reproduced the exact tokenizer SHA256. Its fitting sample was 9,295,401 UTF-8 bytes; measured peak process RSS was 103,600 KiB (about 101 MiB), including CLI/SQLite/native tokenizer memory. This is one measured candidate fit, not a general memory bound for larger fitting budgets.
